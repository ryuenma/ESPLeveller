# antislop audit 001 — ESP Leveller

Date: 2026-10-01
Mode: 2 (audit after the fact). Scope: `ESP_Leveller.ino` (firmware + embedded web UI), `README.md`.
Method: read, contrast formula, and a real click-through of the extracted web UI against a mock of the
firmware's HTTP surface (Chromium via Playwright, 390x844 phone viewport). Click-through evidence is in
`anti-slop/evidence-clickthrough.md`.

Dials (this is an existing product, so this is a Design Read of what shipped, not a pre-build declaration):
a handheld reaction game, one focal element (the timer), deliberately uniform. `ENERGY 1 / RHYTHM 1 / MOTION 1`.

---

## HIGH — Hard Gate

### 1. R-26 — the START button is a dead control for the whole round
`#startBtn` stays enabled and clickable while `PLAYING`. Its handler POSTs `/api/start`, which only acts
on `IDLE` and `GAMEOVER`, so nothing happens. The label changes to `...`, which hides the deadness
instead of communicating it. A player who taps it mid-round gets zero feedback.
Evidence: `label while playing: "..." | state PLAYING -> PLAYING | timer kept running: 02.70`.
Fix: disable the button outside `IDLE`/`GAMEOVER` and style the disabled state.

### 2. R-27 — no error state on the one failure that matters: the device dropping off
`#conn` only ever shows `DISCONNECTED` from `EventSource.onerror`, and only *after* a poll-fallback check
fails. Measured: with `/api/events` blocked, the indicator was still empty after 5s, and its box was
`w:0 h:0` (no text node, so nothing renders at all). So for the first three seconds after the stream dies
the player sees nothing at all, and for a first connect that never succeeds the fallback is only reached
if `onerror` fires inside the 3s window.
Fix: show a live reconnect banner the moment SSE is not open, and start the fallback from the error event
rather than from a 3s timer.

> Correction, added after review: I originally wrote here that the 3s fallback "cannot be reached". That is
> wrong. `EventSource` fires `onerror` when the initial connect fails, so `$('conn').textContent` really can
> read `DISCONNECTED` before the timer runs, and the fallback did start. The finding stands on the
> three-second silence and the 0x0 indicator, not on unreachability.

### 3. R-25 — one text pairing fails AA
`.info` (`WiFi: ESPLevellerAP · 192.168.4.1`) is `#666` on `#111` = **3.29:1**, below the 4.5:1 floor for
normal text at 0.8rem. Every other pairing passes: body 16.28:1, `#status` states 8.88-11.84:1,
`.small` 6.63:1, buttons 13.71:1, `#startBtn` 8.19:1.
Fix: `#666` -> `#999` (6.63:1, matches `.small`).

### 4. R-32 — no accessible name on the two threshold steppers
`#minus` and `#plus` contain only the glyphs `➖` / `➕`, so their accessible names are the emoji
themselves. There is no `aria-label`. A screen reader announces "minus button" at best, and the raw emoji
name at worst. `thrSlider` has no `<label for>` either (there is a nearby `<span>`, which does not label it).
Fix: `aria-label="Decrease threshold"` / `"Increase threshold"`, and a real `<label for=thrSlider>`.

### 5. R-32 — live state changes are never announced
`#status`, `#timer`, and `#tiltbar` have no `role` and no `aria-live`. A screen-reader user gets no
confirmation that the round started, ended, or what the final time was: the only signal is visual.
Fix: `aria-live="polite"` on `#status`, and an `aria-label` on `#tiltbar` carrying the tilt/threshold.

---

## MEDIUM — Purpose-Gate

### 6. R-31 / R-37 — the design has no written direction
There is no `DESIGN.md`, and the reasoning behind the palette, the monospace timer, and the single-column
phone layout exists nowhere. R-31 makes a decision invalid if its reason cannot be written in one line, so
right now none of these decisions are recorded.
Fix: a short `DESIGN.md` with the dials and one line per decision.

### 7. R-29 — the accent colour is doing three jobs
`#0af` is the accent on the slider, the tilt bar fill, and the START button, while `#fa0` (warn) and
`#f33` (bad) sit beside it. That is three saturated hues on one screen, past the 2-3 core + 1 accent line.
The three are justified in practice (safe / warning / fail is the game's whole vocabulary), but nothing
says so.
Fix: state the reason in `DESIGN.md` rather than restyling.

### 8. R-27 / C-4 — the tilt bar keeps its alarm state after the round is over
Returning to the menu after `GAMEOVER` leaves the bar at `100%` and `.bad` (red) while the status reads
`IDLE`. Evidence: `at GAMEOVER: fillW 100% fillClass bad | back at IDLE: fillW 100% fillClass bad`.
The device keeps publishing live tilt, so a device left tilted reads as "failing" on the menu.
Fix: reset the bar when entering `IDLE` from `GAMEOVER`.

### 9. R-25 (non-text) — the reconnect indicator has no box
`#conn` is `position:fixed` with 12px text and no padding or border, so at rest it occupies `0x0` and only
becomes visible when it has text. It also has no icon or text prefix, so its meaning rests on red alone
(color-only feedback, C-4).
Fix: give it a real pill background and a text label.

### 10. R-28 — no FAQ, correctly
There is no FAQ section. Nothing to fix; recorded so the absence reads as a decision, not an oversight.

## LOW — Quality Locks

### 11. R-02 — em dashes in agent-authored text
11 in the sketch (mostly comments and two `SLOG` strings) and 22 in the README. The README is a
documentation file, so the ban applies.
Note: the sketch's own header comment is documentation-of-intent and reads as engineering prose, not UI
copy. Applying the ban there is the strict reading; the two `SLOG` strings and the README are clearly in
scope. Proposing: fix README + the two `SLOG` strings, and leave the header block, flagged here for the
owner to overrule.
Fix: replace with commas, colons, or parentheses.

### 12. antislop-code — 11 decorative separator banners
`// ---------------- GAME STATES ----------------` and friends. The decoration is the message. Two of them
(`// ---------------- GAME VARIABLES ----------------`, `// ---------------- GAME STATES ----------------`)
also sit on adjacent lines and can collapse into one.
Fix: plain `// Game states`, no rules.

### 13. antislop-code — comment alignment churn
25 inline comments are column-aligned with runs of 2-24 spaces. Where the run does not line up with its
neighbours, it is noise. The `BMI160` register block (lines 132-138) is the worst: 7 comments each padded
to a different column.
Fix: single space, or align per block and never across.

### 14. R-30 / C-1 — the UI still says BARRETT
`<h1>🛡 BARRETT LEVELLER</h1>` is the one user-visible string the rebrand in `a7a786d` missed. Every other
surface says ESP Leveller, including the `<title>`, the firmware header, and the README. This is a real
bug, not only a rule break: users see the old product name on the game screen.
Fix: `ESP LEVELLER`, and drop the decorative shield (R-36, emoji in a heading carries no information).

### 15. R-35 — no click-through was recorded before release
The UI shipped with no recorded evidence that any control was exercised. This audit is the first.
Fix: keep `anti-slop/evidence-clickthrough.md` in the repo.

### 16. R-32 (advisory) — `thrSlider` and `#snd` are under 44px
`thrSlider` measures 214x16 and `#snd` 13x13. The slider is the primary threshold control on a phone and
its track is a 16px target. This passes WCAG 1.4.10 reflow (verified clean at 320px and 400px) and is a
Hard-Gate R-03 concern only if it blocks the task, which it does not. Reporting as advisory.
Fix: grow the slider hit area with padding or a taller thumb.

## Verified PASS (not findings)

- **R-02 in the rendered UI**: the web page contains no em dashes. Its separator is `&bull;`.
- **R-03 mobile**: no horizontal overflow at 390px, 320px, or 400px. `startBtn` 358x58, `calBtn`/`abortBtn`
  175x51, `minus`/`plus` 64x51 all clear 44px.
- **R-32 focus ring**: real keyboard `Tab` gives `outline: 1px auto`, and `:focus-visible` matches. No
  `outline:none` anywhere. (An earlier programmatic `.focus()` read showed no ring; that was a headless
  artifact, not a defect.)
- **Keyboard operation**: `Enter` on `#minus` moved the threshold 15deg -> 14deg. Tab order follows visual
  order: `thrSlider -> plus -> snd -> calBtn -> abortBtn -> startBtn`.
- **WCAG 1.4.4 text resize**: at 200% root font size, no overflow and zero clipped elements.
- **WCAG 1.4.10 reflow**: clean at 320px and 400px.
- **R-26 working controls**: `CALIBRATE` zeroes the tilt, `STOP` ends the round and shows `FINAL`, `BACK TO
  MENU` returns to `IDLE`, the slider gives live feedback then commits, `START` starts a round.
- **R-35 build/run**: the UI was served and every control exercised against a mock of the firmware surface.
- **Firmware honesty check**: `random(2000, 5001)` is genuinely random here. arduino-esp32 defaults
  `random()` to the hardware TRNG (`esp_random()`) and only falls back to a seeded LCG if `randomSeed()`
  is called, which this sketch never does. The "random countdown" claim holds, no fix needed.
